# 01.1 - Project Vision & Core Paradigm

## The Problem
Modern cloud engineering is fragmented across three distinct paradigms:
1. **Infrastructure as Code (IaC)**: Tools such as Terraform provision cloud resources (VPCs, Subnets, EC2, RDS, S3) declaratively.
2. **Configuration Management**: Tools such as Ansible configure OS packages, runtime services, system users, and firewall rules sequentially.
3. **Container Orchestration**: Tools such as Kubernetes manage container deployments, services, ingress controllers, and storage volumes.

Engineers are forced to maintain mental context across three separate toolchains, write boilerplate YAML and HCL manually, troubleshoot syntax errors in CI pipelines, and struggle to visualize multi-tier system topologies.

---

## The InfraCanvas Solution
InfraCanvas (internally referenced as InfraFlow) unifies Terraform, Ansible, and Kubernetes into a single **interactive visual canvas**.

Instead of writing infrastructure code by hand:
- Users drag modular blocks onto a graphical viewport.
- Connecting nodes establishes topological dependencies (for example: `VPC` -> `Subnet` -> `Security Group` -> `EC2 Instance` -> `Nginx Web Server`).
- Parameters are configured via an interactive inspector panel.
- The platform compiles the visual graph into a valid, production-ready DevOps bundle (`terraform/`, `ansible/`, `k8s/`).
- Users execute deployments directly against a simulated local sandbox (LocalStack + SSH containers) or real cloud providers, observing real-time per-node execution status.

## Core Tenets & Architectural Philosophy

### 1. Dual-Directional Reality (Visual & Code Equivalence)
Visual diagrams are strictly coupled with executable infrastructure primitives. Modifying a parameter on the visual inspector updates the generated code in real time; importing existing HCL or YAML files reverse-synthesizes corresponding visual nodes with topological connections (see [[02.4 - HCL and YAML Reverse Importer AST]]).

### 2. Zero-Risk Local Sandboxing
Deploying cloud infrastructure during early iteration can incur costs and create security liabilities. InfraCanvas bundles a simulated cloud environment (LocalStack for AWS APIs and Docker SSH containers for virtual machines), enabling developers to execute real `terraform apply` and `ansible-playbook` runs locally without cloud expenditure (see [[03.2 - DevOps Sandbox (LocalStack & SSH Containers)]]).

### 3. Separation of Concerns
- **Frontend** (`apps/web`): Focuses on reactive visual graph manipulation (@xyflow/react), state management (Zustand), syntax compilation, and responsive UI presentation.
- **Backend** (`apps/api`): Focuses on authorization, RBAC, encrypted credential storage, process execution orchestration (Go runner), WebSocket stream distribution, and persistence.

### 4. Zero External Database Daemons for Development
The backend uses pure Go SQLite (`modernc.org/sqlite`) and an in-process runner, allowing the entire stack to boot via standard `npm run dev` or `docker compose up` without requiring external database setups.

## Target Personas & Use Cases

| Persona | Primary Value Proposition |
| :--- | :--- |
| **DevOps Engineers** | Visually prototype multi-cloud architectures, auto-generate boilerplate HCL/YAML, and export deployable zip bundles. |
| **Full-Stack Developers** | Self-serve cloud and VM environments without needing deep expertise in Terraform state management or Ansible syntax. |
| **Solutions Architects** | Design infrastructure in real-time collaboration with teammates and export living, executable architecture blueprints. |
| **Students & Learners** | Experiment with cloud provisioning and server configuration safely inside a free local Docker sandbox. |
