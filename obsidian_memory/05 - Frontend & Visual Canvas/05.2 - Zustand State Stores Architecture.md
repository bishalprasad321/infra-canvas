# 05.2 - Zustand State Stores Architecture

## Client State Management

InfraCanvas uses **Zustand** for lightweight and reactive global state management across the Next.js frontend without the rendering overhead of React Context.

The application relies on two primary stores:
1. **`useCanvasStore`** (`apps/web/app/store/useCanvasStore.ts`): Manages visual nodes, connection edges, viewport coordinates, execution status tracking, canvas interaction modes, and debounced auto-save buffers.
2. **`useAuthStore`** (`apps/web/app/store/useAuthStore.ts`): Manages authenticated user identity, JWT session tokens, active team selections, and billing tier permissions (`FREE`, `PRO`, `ENTERPRISE`).

## Debounced Auto-Saving Architecture

When nodes are dragged or parameters are edited:
1. `useCanvasStore` updates local React state immediately (optimistic UI).
2. A 1500ms debounce timer is triggered.
3. If no further mutations occur within 1500ms, the store dispatches a background `PUT /api/projects/{id}/canvas` payload containing the serialized node graph, connection edges, and viewport zoom coordinates along with the current `version`.
4. Successful response increments the local `version` counter.
